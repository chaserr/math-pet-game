变更协议（项目准则）

所有业务/交互/数据/资源规范变更必须：
1️⃣ 改代码
2️⃣ 更新本知识库对应模块页面的现状描述
3️⃣ 在 沟通日志 顶部追加一条 <article class="entry">（含日期、回合号、用户原话、决策、影响文件）
4️⃣ 文档与代码同回合提交，不允许"先合代码后补文档"

多页结构约定

  • 主页 index.html 仅做卡片导航；每个模块/章节是独立 HTML
  • 公共样式 shared.css + 公共脚本 shared.js（侧栏高亮 + 跨页搜索），所有页 <link>/<script> 引用
  • 新增页面后：① 在 index.html 卡片网格加一张卡 ② 在所有页面的 <aside class="sidebar"> 加导航项 ③ 在 shared.js 的 PAGES 数组加一项（供搜索）

禁止

  • ❌ 新建独立的 Markdown 规范文档（旧 DESIGN.md 仅作历史归档）
  • ❌ 把规范写在代码注释里替代知识库
  • ❌ 删除 changelog 历史条目（只能追加）
  • ❌ 把多个模块塞回单一 HTML（保持多页结构）
本结构（index 主页 + 各模块独立 HTML + shared.css/js）已被定为后续任何项目的文档总纲。
