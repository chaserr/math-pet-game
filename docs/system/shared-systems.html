关卡进度（localStorage v3）shared v1.4 重构

文件：src/lib/progress.js
存储键
mpg_progress_v3（JSON 对象，v2 → v3 不迁移）
数据格式
{"math.add.within10": [1,2,5,...], "math.add.within100": [1], "chinese.recognize.default": [1,2,3]}
按 subject.module.category → 已通关关号数组（去重+升序）
无分类模块
语文/英语用 category = 'default' 兜底
API
getClearedSet(s, m, c) → Set<number>（已通关关号集合）
clearedCount(s, m, c) → 已通关关数
isStageCleared(s, m, c, stage) → 该关是否通关
markCleared(s, m, c, stage) 把 stage 加入集合；返回是否首次通关
nextChallengeStage(s, m, c, total) = max(cleared) + 1，封顶 total
设计取舍
集合而非最高数：支持单关灰显与重玩；关卡可任意顺序通关，没有"回退"概念
不上 Supabase
JSON 体积小；想跨设备同步时再升级

云端读缓存兜底 api v1.6.6 新增

文件：src/lib/cloudCache.js · src/lib/cloudHealth.js · src/db.js（withCache）

国内→AWS（Supabase）链路抖动严重，db.js 的云端读会经常失败。为防止 UI 空白，引入 LocalStorage 缓存兜底。 

cloudCache.js
  key: mpg_cache_v1_<uid|guest>_<topic>
  api: cacheGet / cacheSet / cacheClear / cacheAge

cloudHealth.js (响应式单例)
  cloudHealth.offline: boolean         // App.vue 顶部 banner 订阅
  markCloudOnline() / markCloudOffline(topic)

db.js withCache(topic, fetcher, fallback)
  成功 → cacheSet + markCloudOnline + 返回 data
  失败 + 有缓存 → markCloudOffline + 返回缓存
  失败 + 无缓存 + 有 fallback → markCloudOffline + 返回 fallback
  失败 + 无缓存 + 无 fallback → throw

包装的 read 函数：
  getProfile  → topic 'profile', fallback {points:0, mainLevel:1}
  listMyPets  → topic 'myPets',  fallback []
  listMyFoods → topic 'myFoods', fallback {}
  getShop     → topic 'shop',    fallback 用静态 PETS/FOODS + owned=false

UI：
  App.vue offline=true 时滑下黄色 banner，点击可隐藏；
  下次恢复在线再下次失败重新出现。

写操作（buyPet / feed / submitRound 等）不缓存，失败仍抛错 + 走原有乐观 UI。多账号切换：cache key 按 userId 隔离，互不干扰。
